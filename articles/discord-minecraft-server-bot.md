## 「鯖立てて」

自宅のWindows PCでマイクラ（Minecraft）のサーバーを動かしていて、フレンドとマルチをやっていると、遊ぶたびにこの連絡が来ます。自分がPCの前にいないと始まらないし、自分が寝落ちすると翌朝までつけっぱなし。

サーバー自体は動くようになったのに、**起動できるのが自分だけ**なせいで、自分が待ち合わせのボトルネックになっていました。

なので、DiscordのチャンネルでBotに `/start` と打てば、自宅のマイクラサーバーが遠隔で立ち上がるようにしました。フレンドが自分で打てます。EC2やGCPのようなクラウドではなく、**自宅サーバー（Windows PC）をそのまま使う**構成です。

`/start` を打つと、しばらく「考え中」の表示が出たあと、チャンネルにこう返ってきます。

```
サーバーを起動したのだ！
接続先: <グローバルIP>:25565
```

フレンドはこの1行をコピーして、マイクラの「サーバーを追加」に貼るだけです。

| コマンド | 何が起きるか |
| --- | --- |
| `/start` | サーバーを起動して、接続先アドレスを返す |
| `/end` | サーバーを正しい手順で終了する |
| `/status` | 起動しているか＋今何人いるかを返す |

動かしているのは、マインクラフト Java版のサーバー（ポート25565）と、Python（discord.py）で書いた常駐のDiscord Botです。

Botの返事が「〜のだ」口調なのは、アイコンに合わせた遊びです。以下、まず**なぜそう作ったか**を書き、そのあとに**同じものを作る手順**をまとめます。後半は「実はこれ、AIエージェントに作らせた」という話と、**レビューで実害のあるバグが1件見つかった**話です。

## 設計1：マイクラサーバーの起動・停止ロジックをBotに再実装しない

自宅PCには、もともとマイクラ鯖を起動・停止するPowerShellスクリプトが2本ありました。

- `mc_start.ps1` … javaを起動し、ポート25565が接続を受け付けるまで待つ（最大120秒）
- `mc_stop.ps1` … RCONで `list` → `save-all flush` → `stop` を送り、プロセスが消えるまで待つ（最大90秒）

**今回作ったのは、これをDiscordから呼ぶ入口だけ**です。Botの中でjavaを起動したくなりますが、やりません。

```python
cmd = [PS_EXE, "-NoProfile", "-ExecutionPolicy", "Bypass", "-File", script_path]
completed = subprocess.run(cmd, capture_output=True, timeout=timeout_sec)
```

判定はスクリプトの標準出力の文字列で行います。`ALREADY_RUNNING` なら「もう起動していた」、`READY listening_on=` なら「今起動した」。**この2つは終了コードがどちらも0**なので、文面を書き分けたいなら標準出力を見るしかありません。

マイクラ側の設定（メモリ、javaのパス、待ち時間）が変わってもBotを触らずに済む代わりに、**出力文字列を変えるとBotが静かに壊れる**リスクを背負います。そこは後述のテストで縛りました。

なお `subprocess` にはリストで渡し `shell=True` は使いません。そもそも**引数を取るコマンドを1つも定義していない**ので、ユーザーの入力がコマンドラインに載る経路が構造的にない。

## 設計2：マイクラサーバーの停止は必ずRCON経由。強制終了するとワールドが壊れる

**この記事で一番言いたいのはここです。**

マイクラサーバーを止めるとき、`Stop-Process -Force` や `taskkill /F` でjavaを殺してはいけません。サーバーは終了処理の中でワールドを保存するので、そこを飛ばすと**最後の保存以降が消えます**。

停止側は、既存スクリプトのこの順序を崩さないようにしました。

1. RCONで `list`（誰がいるか記録）
2. RCONで `save-all flush`（保存を完了させる）→ 3秒待つ
3. RCONで `stop`
4. プロセスが消えるまで最大90秒待つ
5. 消えなければ、**強制終了せずに失敗として報告する**

Bot側には `kill` に相当するコードを1行も置いていません。「応答しないから殺す」分岐を持たせた時点で、いつか誤爆します。

押さえておきたいのは、**Bot側のタイムアウトで打ち切られるのは `powershell.exe` だけ**という点です。javaは `Start-Process` で独立プロセスとして起動され標準出力もファイルへ逃がしているので、PowerShellを打ち切ってもマイクラ本体には波及しない。ここが繋がっていたら、タイムアウトのたびにワールドが不正終了していたことになります。

そのタイムアウト値も地味に効きます。当初はスクリプト側の待ち時間の合計に対して余裕が薄く、**RCONがもたつくと「正常に止まっているのに失敗と表示される」**余地があったので180秒まで上げました。誤報が出る先はフレンドの見るチャンネルなので、余裕は厚いほうへ倒します。

## 設計3：Discordのスラッシュコマンドは3秒以内に応答しないと失敗する

スラッシュコマンドは、**最初の応答を3秒以内に返さないとエラー**になります（トークンが無効になる）。一方でマイクラサーバーの起動は1分近くかかる。素直に「起動してから結果を返す」と書くと**必ず失敗します**。

解決策は、先に「考え中」にしてしまうことです。

```python
await interaction.response.defer(thinking=True)   # ここで3秒制限をクリア
result = await asyncio.to_thread(run_ps_script, script, timeout)  # 1分かかってよい
await interaction.followup.send(message)          # 結果は followup で送る
```

`defer()` を打つとDiscord側は「Botが考え中」の表示になり、あとは15分以内に `followup` で本文を送ればよくなります。

注意点が1つ。**権限チェックのような「弾く処理」は `defer()` より前**に置き、`response.send_message(..., ephemeral=True)` で本人にだけ返します。`defer()` の後に `response.send_message` を撃つと二重応答になるので、拒否パスと正常パスで使うメソッドが変わります。

## 設計4：Discord Botのステータスで、今サーバーが動いているか分かるようにする

このBotは自宅PCの上で動くので、**PCが落ちていればBotもオフライン**です。そのときフレンドに何が見えるかは確かめておきたくて、Botを落とした状態で `/status` を打ってみました。結果は、**打った本人にだけ「アプリケーションが応答しませんでした」と表示され、チャンネルには何も残らない**。気づかずに連打されてもチャンネルは荒れない。これが分かって、安心して配れるようになりました。

とはいえ「打つまで分からない」のは不親切なので、Botのステータス（メンバー一覧で名前の下に出る一言）をマイクラの状態に合わせて書き換えています。

| 一言 | 意味 |
| --- | --- |
| （出ない・灰色） | PCが落ちている。今は繋がらない |
| `マイクラ待機中なのだ` | PCは動いていて、マイクラは止まっている |
| `マイクラ起動中なのだ` | 動いているが誰もいない（または人数が取れなかった） |
| `◯人でマイクラ中なのだ` | 動いていて、◯人が遊んでいる |

実際に動かしたところ、フレンドが4人入っている状態で `4人でマイクラ中なのだ` と出ることは確認できました。コマンドを打たなくても、メンバー一覧を見るだけで「今つながるのか」が分かります。

人数はRCONで `list` を叩いて取っています。気をつけたのは、**人数が取れなくても表示機能ごと壊さない**ことです。

```python
if not online_count:  # None（取れなかった）と 0（誰もいない）は同じ扱い
    return "マイクラ起動中なのだ"
return "{}人でマイクラ中なのだ".format(online_count)
```

RCONは起動直後などまだ受け付けていない瞬間があります。そこで例外が抜けて更新ごと止まると、**「人数が出ない」で済むはずの不具合が「表示が固まる」に化けます**。落ちたら粗い文言に落として、機能は生かす。

更新は60秒ごとのポーリングですが、送信にはレート制限があるので**文言が前回と変わったときだけ送る**ようにしました（`/start` `/end` の直後は即時更新）。

## 設計5：接続先アドレスと、コマンドを打てるチャンネルの制限

`/start` に成功すると `接続先: <アドレス>:25565` の1行を添えます。このアドレスは固定で書かず、**起動のたびに取得**しています。グローバルIPは変わりうるので、固定にすると「Botが古いアドレスを自信満々に案内する」状態になる。これが一番たちが悪い。取得に失敗したら、その行だけ省いて「起動した」は返します（外部公開そのものは別の話なので触れません）。

打てる場所も絞っています。設定でサーバー（ギルド）とチャンネルのIDを指定し、それ以外では動きません。コマンドは指定サーバーにだけ登録しているので他所では候補にも出ませんが、実行時にもチェックしています。

`/end` は既定で全員が使えますが、**押すと全員切断される**ので「押す前に `/status` で誰もいないか確認して」と案内しました。Botトークンはソースにも設定ファイルにも書かず、環境変数か別ファイルから読みます。あと `server.properties` にはRCONの認証情報が平文で入るので、サーバーフォルダを丸ごと誰かに渡すときは注意してください。

## 作り方：同じものを自分で用意する手順

ここまでの構成を自分で作るときの手順です。Discord側の画面は表記も配置もよく変わるので、名前が違っていたら**近いものを探してください**。

### 用意するもの

- Python と `discord.py`（`pip install discord.py`）
- **マイクラサーバーを起動・停止できるスクリプトが、既に手元で動くこと。** Botはそれを呼ぶだけなので、ここが無い人はまずそちらからです（設計1）
- Discordのサーバー（ギルド）と、コマンドを打つチャンネル

### 1. Discord側でBotを作る

1. [Discord Developer Portal](https://discord.com/developers/applications) を開き、アプリケーションを新規作成する
2. 左メニューの `Bot` を開き、`Reset Token` でトークンを発行してコピーする
3. **トークンはこの1回しか表示されません。** 見失ったら再発行になり、その瞬間に古いトークンは無効になります
4. `Privileged Gateway Intents` は全部OFFのままで動きます（スラッシュコマンドしか使わず、チャットの本文を読まないため）

### 2. Botをサーバーに招待する（ここでつまずきました）

スコープに **`bot` と `applications.commands` の2つ**を付けて招待します。権限は `Send Messages` があれば足ります。

- **`applications.commands` を入れ忘れると、`/` を打ってもコマンドが1つも出てきません。** 一番ありがちなつまずきです。入れ直して招待リンクを開き直せば直ります
- 招待リンクは `Installation` から作る手順をよく見かけます。ただし**自分のDeveloper Portalは日本語表示になっていて、`Installation` に当たる項目を見つけられませんでした**
- そのときは **`OAuth2` → `URL Generator`** で、`SCOPES` に上の2つ、`BOT PERMISSIONS` に `Send Messages` をチェックすると、下に招待URLが出ます。**自分はこの経路で招待まで完了しました。** `OAuth2` は日本語表示でも英語のまま出ていました

### 3. IDを調べて設定に書く

Discordのサーバー・チャンネル・ユーザーには、それぞれ長い数字のIDが付いています。

1. Discordの `ユーザー設定` → `詳細設定` で **開発者モードをONにする**
2. サーバー名を右クリック → `サーバーIDをコピー`
3. チャンネル名を右クリック → `チャンネルIDをコピー`

設定ファイルはこんな形です（**値はすべてダミー**）。

```json
{
  "guild_id": "123456789012345678",
  "allowed_channel_ids": ["234567890123456789"],
  "server_port": 25565,
  "start_timeout_sec": 180,
  "stop_timeout_sec": 180
}
```

タイムアウトは、**起動・停止スクリプト側の待ち時間の合計より長く**します。短いと、正常に進んでいるのに「失敗」と表示されます（設計2）。**トークンは設定ファイルに書かず**、別ファイルか環境変数から読ませます。

### 4. 起動して動作確認する

1. Botを起動し、**メンバー一覧でオンラインになる**ことを確認する
2. チャンネルで `/` と1文字打ち、`start` `end` `status` が候補に出ることを確認する
3. **まず `/status` から試す。** 何も起動しないので、いちばん安全な確認方法です
4. 次に `/start`、最後に `/end` を試す

コマンドをサーバー限定で登録している場合、反映は即時とされています（Discord公式ドキュメントの記載）。それでも出ないときは `Ctrl + R` でDiscordを再読み込みしてみてください。

### 5. 常駐させる

PCにログオンしたらBotが自動で立ち上がるようにしておくと、こちらは何もしなくてよくなります。

- タスクスケジューラで「ログオン時」に起動する。**登録には管理者権限が要ります**
- 管理者権限を使いたくなければ、**スタートアップフォルダ**（`Win + R` → `shell:startup`）にショートカットを置く方法もあります
- Windowsでは `pythonw.exe` から起動すると黒い窓が出ません。そのぶん、様子はログファイルで見ることになります

### つまずいたときに見るところ

| 症状 | 見るところ |
| --- | --- |
| `/` を打ってもコマンドが出ない | 招待時の `applications.commands`。入れ直して招待し直す |
| Botがオフラインのまま | トークンが違う可能性。ログに認証エラーが出ていないか |
| 「このチャンネルでは使えない」と返る | チャンネルIDの設定違い。**スレッドは本体と別のIDを持つ**ので、チャンネル本体で打つ |
| `/start` が失敗する | Bot経由ではなく、**起動スクリプトを手で叩いて動くか**を先に確認する |

## ここから本題：これ、AIエージェントに作らせています

ここまでの実装、自分でガリガリ書いたわけではありません。**実装役のAIエージェントに作らせ、別のレビュー役のAIエージェントに叩かせる**という進め方をしています。

### レビューで見つかった、実害のあるバグ

レビュー役が1件、実際に困るバグを見つけました。**Discordに再接続するとステータス表示が「マイクラ待機中なのだ」に戻り、そのまま二度と復帰しない**というものです。

1. `change_presence()` は**ゲートウェイに送るだけ**で、再接続時に送り直す値（内部に保持しているactivity）を更新しない
2. 再接続時のIDENTIFYは、その**内部の値**をそのまま送る → 表示が初期文言に戻る
3. Bot側は「今こう表示しているはず」の値を別に持っていて、**そちらは元に戻らない**
4. 結果、次の更新で「文言は変わっていない」と判定され、**送信をスキップし続ける**

設計4の「変わったときだけ送る」というレート制限対策が、再接続時にちょうど裏目に出る形です。実害は、**遊んでいる最中にステータスが「待機中」と表示され続ける**こと。打つ前に状況が分かるように、という目的が裏返ります。

修正は1行でした。

```python
await bot.change_presence(activity=_activity(text), status=discord.Status.online)
bot.activity = _activity(text)   # ← 再接続時に送り直される値も更新する
```

### 「直した」で終わらせない

面白かったのはここからで、**修正が効いているかを、修正を外して確かめました。**

上の1行だけを削除した写しを作って同じテストを流したところ、「再接続で送り直される文言」が期待値と食い違って**テストが落ちました**。修正入りでは通る。テストが通っただけだと「そもそも検出できていない」可能性が残るので、**1行外して落ちることまで見て初めて回帰テストとして機能する**と思っています。

回帰テストは現在98件。効いているのは、`mc_start.ps1` / `mc_stop.ps1` / `rcon.py` を**読み取りだけで開き、Botが依存している文字列**（`READY listening_on=` `EXITED cleanly` など）**が今も存在するか**を検査するテストです。設計1で背負ったリスクを、ここで落とします。

### AIに書かせるなら、独立した目でレビューさせる

誇張せずに書くと、これは**AIが書いたから出たバグではありません**。ライブラリの内部挙動に依存する種類のもので、人間が書いても普通に踏みます。

効いたのは**作った本人以外に見せたこと**のほうです。成果物と一次資料だけを渡された別のエージェントは、実装時の思い込みを引き継がずに読めます。今回もレビュー役はライブラリのソースを開いたうえで指摘してきました。変えたのは**渡す情報と役割を分けたこと**だけです。

なお、この修正が実運用の再接続で効くことは、まだ観測できていません（テスト上は再現・修正を確認済み）。

## まとめ

1. **停止は必ず正規手順（RCON）で。強制終了は入れない。** ワールドが壊れる
2. **Discordは3秒以内に応答が要る。** 重い処理は `defer()` → `followup` に分ける
3. **AIに書かせたコードは独立した目でレビューさせる。** 修正が効くことは、修正を外して確かめる

この記事を書いている今も、自分は入っていないのにフレンドだけで4人が遊んでいます。待ち合わせのボトルネックが、自分ではなくなりました。
